What appeared to be a routine festival phishing link was identified through Burp Suite interception and manual JavaScript deobfuscation as a professionally engineered five-stage operation. The campaign combines a polymorphic cloaking engine, a Vue 3 single-page application with Pinia state persistence, a self-propagating WhatsApp worm requiring 19 forced shares, a CPA ad fraud loop with a rigged 70% rejection rate, and a persistent WebSocket Command-and-Control backdoor capable of executing arbitrary JavaScript inside a victim's mobile browser in real time.

The kit correctly evaded VirusTotal because desktop security scanners receive only a 404 decoy — the real payload is served exclusively to mobile browsers that pass a triple environment check. This report documents the full five-stage architecture, the attack chain, all identified indicators of compromise, and the remote code execution sink discovered in the C2 module.

Stage Analysis

STAGE 1 Polymorphic Gateway & WhatsApp Preview Spoofing HIGH

The entry URL encodes campaign metadata across four parameters: a rotating 10-character slug evading URL blocklists, a country-language code (in-en), a 19-digit referral token (first 15 digits = sharer's victim ID, last 4 = random entropy), and a Unix timestamp recording share creation time.

WhatsApp OG Tag Spoofing

The gateway serves crafted Open Graph tags that cause WhatsApp's link preview crawler to display a convincing Airtel-branded card with og:url set to https://whatsapp.com — bypassing the most basic defence of checking the URL:

<title>🪔Airtel - ദീപാവലി സമ്മാനം!🎁</title>
<meta property="og:url" content="https://whatsapp.com">
<meta property="og:description" content="₹2,000 ...">

Polymorphic Cloaking — Variable Name Mutation

The inline bouncer script regenerates with entirely new variable names on every server request, defeating hash-based AV signatures:

// Three consecutive captures, identical logic, different names:
Capture 1: KMKBDs, beIkdB, OmBMan, SXJoVX, pbtDry

When decoded the logic is identical — a triple environment check: navigator.platform for Win/Mac/X11, availWidth > availHeight for landscape screens. Desktop browsers receive a 404 decoy. Mobile phones are redirected to a time-gated 90-character single-use token URL.

STAGE 2 Vue 3 SPA — Victim Profiling, Fake Social Proof & Browser Lockdown HIGH

Mobile visitors receive a compiled Vite + Vue 3 SPA (MyAppVersion: 2561). Developer debug strings in Simplified Chinese confirm core kit authorship by Chinese-speaking threat actors. Pinia v2.3.1 with localStorage persistence ensures victim progress survives tab closes.

STAGE 4 CPA Ad Fraud — Rigged Payout Gate MEDIUM

After 19 shares, victims must complete 3 "sponsor tasks." Two gates ensure victims almost never succeed:

// Gate 1: Return in under 10s → rejected, another ad click forced
if (JSON.parse(localStorage.getItem("clickTaskTime")) > Date.now()) {
    rI(e); // force new ad click
    return false;
}

// Gate 2: 70% artificial rejection even after waiting 10+ seconds
if (n.apps >= r.appsMustCount && !(Math.random() < r.appsPercent)) {
    // appsPercent = 0.3 → fails 70% of the time
    rI(e);
    return;
}

Statistically requires 6–8 additional ad clicks per task (1/0.3 ≈ 3.3 attempts per task × 2 remaining tasks). Even victims who complete all tasks reach a static text paragraph — no payment gateway, no UPI integration, no reward ever delivered.

STAGE 5 WebSocket C2 Backdoor — Remote Code Execution CRITICAL

Two seconds after the SPA mounts, a WebSocket C2 module is silently injected from the Node.js/Express backend with 3-second auto-reconnect and 10-second heartbeat. All console output is suppressed — the WebSocket is invisible in browser DevTools.

The C2 operator receives each victim's phone number, device OS, country, and IP via /api/h5heart/port — enabling targeted payload delivery to high-value victims:

  • Credential overlay injection — replace fake giveaway with spoofed Airtel/bank login or OTP prompt
  • Trojanised APK download — force-download banking malware disguised as reward claim app
  • Victim pivoting — redirect specific targets to secondary exploit kits or WAP billing fraud
  • UPI PIN harvesting — inject payment overlay after victim has been socially conditioned

Why VirusTotal Showed Clean

  • Polymorphic JS — variable names change per request, defeating hash-based signatures
  • Desktop cloaking — VirusTotal scanners receive the 13-byte 404 decoy, never the real payload
  • Time-gated tokens — replaying captured URLs returns no payload (token expired)
  • Cloudflare CDN — legitimate CDN masking infrastructure reputation
  • .buzz TLD rotation — fresh domains cycle before blocklists propagate

Conclusion

This campaign sits well above the typical social engineering phishing kit. The polymorphic cloaking engine, Vue 3 SPA architecture, viral worm propagation, and live WebSocket eval() backdoor place it in the category of a commercially distributed crimeware framework — likely authored by Chinese-speaking threat actors and licensed to South Indian affiliates for the 2026 Diwali campaign cycle.

The most dangerous component is not the credential phishing but the C2 backdoor: any victim with the page open in their mobile browser is compromised at the browser level, with the operator capable of delivering targeted payloads on demand. The social engineering vector — a festival message in the victim's native language from a trusted contact — combined with this technical depth makes the campaign highly effective and resistant to conventional detection.
